Cloud layout

Where those sessions live. Nothing triggers a dataset individually: one scheduled job picks the day's datasets and runs every session inside its single container.

  • Where the model is chosenOPENROUTER_MODEL and OPENROUTER_REASONING_EFFORT are read per session. Provider pins live in MODEL_ROUTING in model_harness.py, keyed by model family.
  • When all 3 attempts failThe batch records failed_attempts on the source and retries it on a later day. Three whole-run failures park it. The live page is untouched.
  • When the account is rejectedA key limit or 403 raises AccountLimitError on the first hit instead of retrying, so a dead key costs one call per source and not three.
  • Sandbox boundaryTool processes get a scrubbed env but can still reach the GCP metadata server and the builder service account. Keep that account minimal.
  • ConcurrencyMany of these run in parallel inside one Cloud Run job container, capped by MAX_CONCURRENT. Parallelism is never Cloud Run autoscaling.
